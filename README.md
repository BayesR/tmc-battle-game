# TMC Battle Game（NPC対戦モード）— Phase 1 プロトタイプ

引き継ぎドキュメント（`TMC_Battle_Game_引き継ぎドキュメント.md`）に基づく Phase 1 実装です。
既存の TMC Battle Simulator（5×5総当たりマトリクス版）とは別アプリとして、
React + TypeScript + Tailwind CSS で構築しています。

## セットアップ

```bash
npm install
npm run dev
```

ブラウザで表示される URL（通常 `http://localhost:5173`）を開いてください。
スマホ実機で確認する場合は `npm run dev -- --host` で同一Wi-Fi内から接続できます。

本番ビルド：

```bash
npm run build
npm run preview
```

Vercelにデプロイする場合は、このリポジトリを新規のVercelプロジェクトとして
（既存シミュレーターとは別プロジェクト・別リポジトリとして）連携するだけで動作します。

## 設計方針（Phase 2・3への拡張ポイント）

- **`logic/` はUIに依存しない純粋関数・Reducerのみ**で構成しているため、
  Phase 2で以下を差し替える際もUIコンポーネントへの影響を最小限にできます：
  - `battleEngine.ts` の `pickEnemyCard()` … 完全ランダム→性格ロジック（ルーズ／クレバー／アグレッシブ）に差し替え
  - `npcDeckGenerator.ts` … ストーリーモードのNPC固定デッキ指定にも流用可能な形にしてある
- **カード解放システム（Phase 2〜3）**：`CardPoolList` に渡す `pool` を
  「プレイヤーが解放済みのカードだけにフィルタしたもの」に差し替えるだけで対応できる設計です。
  進行状況（勝利回数・解放済みカード一覧）は `App.tsx` に `localStorage` 連携のstateを
  追加する形で拡張してください（現状のデッキ保存の仕組みと同様の想定）。
- **ストーリーモード（Phase 3）**：`NpcProfile` に `storyNpcId` 等を足し、
  `npcDeckGenerator.ts` の代わりに「固定デッキ＋テーマLegacy」を返す関数を用意すれば
  `DeckBuilderScreen` / `BattleScreen` 側の変更はほぼ不要です。
- **カードマスターデータの更新**：`convert_master.py` を再実行して
  `TMC_NPC_CardPool.xlsx` を作り直し、シートを新しいJSONに変換して
  `src/data/cardPool.json` を差し替えれば反映されます（列を増やす場合も
  `CardMaster` 型に追記するだけで済むようにしてあります）。

## カードデザイン・対戦盤面（UI改訂）

- **カード表示は画面ごとに2種類**：
  - `CardView`（フル表示・盤面／デッキ構築で使用）：左上=モンスター名／右上=Legacy（名前とLegacyはflexの
    横並びにしてあり、名前が長くても構造的に重ならない）／右端中央=Void（「V」の丸バッジ）／
    左下=Potential Point（「Legacy+数値」表記）／右下=Monster Pride（数字）。
  - `HandCardView`（手札選択用の簡易表示）：Legacyはカード枠の色＋色付き丸のみで表現（文字なし）。
    それ以外の配置（名前TL／Void右端中央／PP左下／MP右下）はCardViewと共通にしている。
  - Monster Prideは⭐️ではなく、常に数字で統一表示する。
  - 邪(Darkness)は背景が暗く視認性が落ちるため、カード枠線とPP文字色を明るく調整している。
- **カード裏面**：「TMC」の太字ロゴ（仮）＋四隅に飾りのある二重線の縁取り。
- **対戦の流れ**：手札からカードを選ぶと「JANO」スタンプが表示され、選んだカードと相手のカードが
  盤面に**裏向き**でプレビュー表示される。**Pull upを押すまでは手札の別のカードをタップして
  何度でも選び直せる**（選び直すたびに相手カードも新しく決め直される）。
  あなた側の裏向きカードには「PULL UP」の表示が出て、タップすると公開され、両方のカードが
  表向きになり、勝敗に応じて「WIN/LOSE/DRAW」のスタンプがカード自体に表示される。
  NEXTを押すと、負けたカードだけ裏返り、次のラウンドへ進む。
- **対戦盤面（BattleBoard）**：ブラウン基調のマット。対戦で使われたカードは盤面に残り続け、
  サドンデス突入時（および同一サイクル内で全戦引き分けて再挑戦する場合）に盤面がクリアされ、
  全カードが手札に戻る。画面幅が足りない場合は横スクロールするが、相手列・自分列は
  1つの共有スクロール領域にまとめてあり、常に一緒に動く（列がずれない）ようにしている。
  最初は左端（1戦目）から始まり、ラウンドが進む・カードを選択するたびに、最新の対戦
  （選択中はPull up前のプレビュー、それ以外は直近のラウンド）が画面内に収まる位置まで
  なめらかにスクロールする。手動でのスクロール操作（過去のラウンドを見返す等）はいつでも可能。
- **対戦相手の見た目**：画面右上の四角い窓枠アイコンの中に、バストアップで表示。
  デフォルトは顔の見えないフードを被った人物のシルエット（`OpponentPortrait.tsx`）。
  プレイヤー自身のアイコンは表示しない方針にしている。
  ストーリーモード（Phase 3）でNPCごとの見た目に差し替えられるよう、単体コンポーネントとして
  独立させてある。
  ※参考画像は今回のやり取りでは受け取っていないため、上記は文面の指示から独自に解釈した
  デザインです。実際の参考イメージがあれば送っていただければ、配色やアングルをより近づけて
  調整します。

## デッキ構築画面の絞り込み・並び順

画面上部の並びは「対戦相手（NPC）の設定」→「自分のデッキ」→「カードプール」の順にしている
（対戦相手を先に決めてから自分のデッキを組む流れを想定）。

`CardPoolList` はカード名の部分一致検索に加え、Legacy（ボタン）・Monster Pride（プルダウン）・
Potential Point（プルダウン、いずれかの枠にそのLegacyを含むかで判定）・Void有無（トグル）で
絞り込みできる。表示順は「同Legacyでグループ化 → Monster Pride高い順 → Potential Point合計値
高い順」に統一。カードはグリッドを常に3列固定にし、間隔を詰めてスマホ幅で3枚並んで見えるように
している。カード一覧部分は独立した領域（`max-height` + `overflow-y: auto`）でスクロールし、
画面全体はスクロールしない構成にしている。また、対戦終了後にこの画面へ戻ったときは常に画面の
一番上から表示されるようにしている（`window.scrollTo`）。

## NPCレベル別プロファイル（テスト実装）

`npcDeckGenerator.ts` の `NPC_LEVEL_PROFILE` に、レベルごとのデッキ構築ルールと対戦時の
出し方（`playStyle`）をまとめている。デッキ生成は `generateLevelTunedNpcDeck()` が担当し、
「必須条件（MP指定・Void必須・Legacy必須）のカードを先に確定 → 残り枠をMonster Pride合計が
目標範囲に収まるようランダム探索」という段階的な構築方式にしている。条件を満たすデッキが
見つからない場合は、既存の汎用ランダム生成（`generateNpcDeck`、BATTLE RULESのみ考慮）に
自動フォールバックする。

| レベル | デッキ構築ルール | 対戦時の出し方 |
|---|---|---|
| Lv1 | 聖・邪不使用／MP合計12〜13／MP5不使用／Void不使用 | 完全ランダム |
| Lv2 | 邪不使用／MP合計14〜15／MP5とVoidを必ず使用 | 完全ランダム |
| Lv3 | 邪不使用／MP合計15固定／MP5・MP1・Voidを必ず使用／PP優先選択 | 初手はMP5・MP1・Voidからランダム、以降ランダム |
| Lv4 | 聖・邪を1枚ずつ以上使用／MP合計15固定／MP5か6・MP1・Voidを必ず使用／PP優先選択 | 初手は同様、以降は自分（プレイヤー）の既出Legacyを予測し相性の良いカードを優先 |

対戦時の出し方は `battleEngine.ts` の `pickEnemyCard()` が `NPC_LEVEL_PROFILE` を参照して
分岐する。「初手」は現在の手札セット（通常5戦・サドンデス各サイクル）でまだ1枚も
出していない状態を指す。Lv4の「相手のLegacyを予測」は、そのマッチ内で自分（プレイヤー）が
これまでに出した（＝公開済みの）カードのLegacyの頻度から最頻のものを推定する処理で、
まだ見えていない現在の手札を覗き見るような実装にはしていない。

見た目（`OpponentPortrait.tsx`）もレベルごとに差し替えている：
Lv1=フードを被った人／Lv2=甲冑の騎士／Lv3=ドラゴン顔のヒューマノイド／Lv4=死神（骸骨と鎌）。
デッキ構築画面のNPC設定パネルにも、選択中レベルの見た目プレビューを表示する。

## 自分のデッキ保存機能・対戦相手デッキの手動作成（今回追加）

- **自分のデッキ保存**：`SavedDeckPanel.tsx` から、選択中の5枚（有効なデッキのみ）に名前を付けて
  `localStorage`（`savedDecks.ts`）に保存できる。保存済みデッキは一覧表示され、「読み込む」で
  即座に選択状態を復元、「削除」で個別に消せる。複数スロット保存可能。
  対戦終了直後の保存タイミングとは独立した、プレイヤーの任意保存の仕組み。
- **対戦相手デッキの手動作成**：`NpcSetupPanel.tsx` に「自動生成」／「自分で作成」の切替を追加。
  「自分で作成」を選ぶと、既存の `DeckSummary` / `CardPoolList` をそのまま流用した選択UIが現れ、
  相手のデッキも自分のデッキと同じBATTLE RULESの下で5枚選んで組める。NPCレベルの選択は
  （デッキ内容には影響しなくなるが）対戦時の出し方（`playStyle`）や見た目（`OpponentPortrait`）
  には引き続き反映される。

## バトルストリート（賭け×収集メタゲーム）

タイトル画面から「バトルストリート」→「NPC対戦モード」→「所持カードリスト」→「オプション」へ遷移する
構成にした（`App.tsx` の `topScreen` で管理）。

- **セーブデータ**：`battleStreetSave.ts` が `localStorage` にバッジ数・所持カードIDを保存。
  初回プレイ時はNカードからMonster Pride 4・3・2・1を各2〜3枚（合計10枚）ランダムに選んで開始する
  （`computeStarterOwnedIds`）。初期バッジ数は現在**テスト用に100**に設定している
  （`STARTER_BADGES`、本番では2に戻す想定）。
- **対戦相手抽選**：`opponentRoster.ts` が4名を独立抽選する。Lv1 40%／Lv2 30%／Lv3 20%／Lv4 9%／
  レアキャラ計1%（神0.1%・ストリートの死神0.4%・チャンピオン0.5%）。レアキャラのデッキ構築は
  Lv4プロファイルを暫定流用している。
- **賭け**：自己申告制。勝てば賭けた分を獲得（実質2倍）、負ければ賭けた分を失う。
- **食事イベント**：バッジ1個以上ならフレーバーテキストのみ。0個の時だけ、3パターンの短い
  シナリオのいずれかが表示されバッジ+1（連打対策として「0個の時だけ」発生する仕様）。
- **パック**：5バッジでノーマル4枚＋確定枠1枚。確定枠は未所持のR/SRからR80%・SR20%の重みで
  ランダムに1枚選ぶ（両方コンプ済みならノーマルへフォールバック）。確定枠はごく低確率で
  UR(0.1%)/SUR(0.05%)/SSUR(0.001%)に格上げされる。重複したカードは無視する方式
  （コンプリートしてもパックが無意味にならない設計）。
- **レアキャラ撃破報酬**：`battleStreetRewards.ts` の `getRareRewardTable` が賭けバッジ数に応じた
  UR/SUR/SSURの確率テーブルを返す（賭け額が大きいほど良いレアリティが出やすい）。外れた場合は
  未所持のSR/Rにフォールバック。
- **NPC対戦モードとの連携**：`App.tsx` がNPC対戦モードに入るたびにバトルストリートの所持カードを
  再読み込みし、デッキ構築画面（`DeckBuilderScreen`）のカードプールをそれに絞り込む。所持カードが
  5枚未満の場合は一時的に全カードで遊べるようフォールバックする。

**保留中の項目（今回は手を付けていない）**：
- レアキャラ（神・ストリートの死神・チャンピオン）専用ビジュアル（現状はLv1〜4の既存ポートレートを暫定流用）
- Bo3（3本先取）システム（バトルストリートでは一旦保留。将来的にNPC対戦モードへの導入をテスト予定）
- 保存済みデッキ（`SavedDeckPanel`）とバトルストリートの賭け対戦時のデッキ選択の統合（現状、賭け対戦では毎回その場で組む形）

- **背景ビジュアル**：バトルストリートの各画面（対戦中を除く）に、承認済みのたこ焼き屋の外観画像
  （`public/assets/battlestreet/shop_exterior.png`）を`position: fixed`で画面全体（ビューポート
  いっぱい）に背景として使用。上に暗めのグラデーションを重ねてテキストの視認性を確保している。
  対戦画面（`BattleScreen`）は既存の盤面デザインをそのまま使うため、この背景は重ねていない。
- **バッジの表示**：`BadgeIcon.tsx` で円形のコイン風アイコンとして統一表示している。

## カードのレアリティ演出（今回追加）

`CardView.tsx` の表向き表示に、`battleStreetRarity` に応じた視覚エフェクトを追加した
（`components/common/RarityEffects.tsx`）。

- **R**：金色の縁取り（box-shadowによるグロー）
- **SR**：斜めに走るキラキラのシャイン（シマー）＋星の瞬き3つ
- **UR・SUR・SSUR**：虹色に輝くホログラフィック効果（アニメーションするレインボーグラデーション、
  `mix-blend-mode: screen` でダーク背景の上でも自然に発光して見えるようにしている）
- **N**：演出なし（通常表示のまま）

**重要な設計判断**：この演出は**表向きの時のみ**表示され、裏向き（`faceDown`）のカードには
一切表示されない。これは、対戦相手の手札やパック開封前のカードのレアリティを、公開前に
視覚的に推測できてしまう（＝ネタバレになる）のを防ぐための意図的な制限。

- **バトルストリートの対戦結果画面**：NPC対戦モードの`ResultScreen`と同じ「対戦の記録」一覧
  （`BattleStreetResultView.tsx`）を表示しつつ、バッジ増減・レアキャラ撃破報酬を追加し、
  ボタンは「バトルストリートに戻る」のみにしている。

## 対戦演出エフェクト（NPC対戦モード・バトルストリート共通）

`battleEffects.ts` の `computeRoundEffects()` が、直近に公開されたラウンドの結果から一度きりの
演出を判定する（NEXTを押すと消える。両モードで共有する`BattleBoard`/`CardView`に実装している
ため、自動的に両方に適用される）。

- **雷**：試合途中（5戦のうち5戦目より前）に、いずれかの側が3勝目を挙げて勝敗が確定した瞬間、
  勝ったカードに雷が落ちる（勝敗確定後も対戦は5戦目まで続行する）
- **Root Counterの光**：Root Counterが発動した側（①のカード）がビカビカ光る
- **切り裂き爪**：Root Counter以外の通常比較で、Monster Pride 5のカードが負けた場合、

## 重大バグ修正：NPCデッキ生成が所持カードに制限されていた問題

**症状**：`DeckBuilderScreen` が、対戦相手（NPC）のデッキ生成にも、プレイヤーの所持カード
（バトルストリートで集めた分に制限されたプール）を使ってしまっていた。典型的なプレイヤー
（所持カード約10〜15枚）でLv4のデッキ生成を試すと、必要なMP5/6・MP1・Void・聖/邪カードが
所持プール内に見つからず、50回中43回失敗して汎用ランダム生成にフォールバックしていた
（＝レベル別ルールが無視されるバグ）ことをテストで再現・確認した。

**修正**：`DeckBuilderScreen` に `fullPool`（所持制限のない全245枚）を新しいpropとして渡し、
NPCの自動生成・手動作成の両方でこちらを使うよう変更した。プレイヤー自身のデッキ構築は
引き続き所持カード制限プール（`pool`）を使う。バトルストリート側は元々全カードプールを
使っており、このバグの影響を受けていなかったことも確認済み。

## ストリートの死神：AIロジックの精緻化

- **Void/聖/邪カードの採用基準**：`reaperCardScore()` を、Void/聖/邪のカードは高レアリティ
  （SR以上）でなければ大きく減点する方式に変更。低レアリティのVoid/聖/邪カードは極力避け、
  高レアリティのものは逆に優遇される。
- **1戦目で負けた場合の2戦目（`pickEnemyCard`の`reaperAI`分岐）**：単に「最も強いカード」を
  出すのではなく、`compareCards()`でプレイヤーの1戦目のカードに対して**実際に勝てるカード**を
  探し、あればそれを出す。勝てるカードがなければ引き分けられるカードを探し、それもなければ
  最も強いカードを最終手段として出す。
- **それ以降の出し方**：以前のLegacy予測方式から、**プレイヤーの既出カードの平均Monster Prideを
  予測し、それを効率よく（最小限に）上回るカードを選ぶ**方式に変更。
- **サドンデス中はこれらの特別ルールを一切適用せず、完全ランダムに戻る**。
