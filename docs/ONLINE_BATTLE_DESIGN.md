# オンライン対戦（フレンド対戦）設計メモ

最終更新：フェーズ0（下準備）完了時点。実装済みの範囲と、これから作る範囲を分けて記載する。

## 基本方針

1. **サーバーが「正」の状態を持つ**：判定はサーバーだけが行う。クライアントは「カードを選ぶ」「次へ」などの意思表示を送るだけ
2. **試合ロジックは純粋なコードにする**：`src/online/` と `src/logic/matchRules.ts` は画面・通信・時間に依存しない。ブラウザでもサーバーでも同じコードが動く
3. **状態は丸ごと送る**：状態が変わるたび、その接続者に見せてよい状態（`OnlineView`）を丸ごと送る。再接続・途中参加（観戦）も「今の状態を1回受け取るだけ」で追いつける
4. **隠すべき情報は送らない**：相手の手札・未公開の選択は、相手にも観戦者にも渡さない（公開されたカードだけが見える）

## 試合の流れ（フェーズ）

```
lobby ──(2人着席)──> deck ──(2人提出)──> pick ──(2人選択確定)──> reveal ──(2人が次へ / 時間経過)─┐
                                          ^                                                      │
                                          └──────────────(まだ続く)───────────────────────────────┤
                                                                                                  v
                                                     finished <──(5戦で決着 / サドンデスで決着 / 不戦敗 / 勝者なし)
```

- 勝敗が確定しても **5戦目まで続ける**（NPC対戦と同じ）
- 5戦で同数なら、同じ5枚に戻してサドンデス。最初に1勝した側が勝ち。1周が全て引き分けならもう一度
- 選択は **確定後に変更できない**（クライアント側で「選ぶ→決定」の2段階にして誤操作を防ぐ）

## 時間と切断（サーバー側のタイマーが、下記のアクションを投入する）

| 状況 | アクション | 暫定値 |
|---|---|---|
| カード選択の時間切れ | `TIMEOUT_PICK`（未選択の席は残りからランダム選択） | 60秒 |
| 結果公開後、確認が揃わない | `TIMEOUT_REVEAL`（自動で次へ） | 8秒 |
| 切断後に戻らない | `FORFEIT { cause: 'disconnect' }`（不戦敗） | 60秒 |
| デッキ未提出 | `FORFEIT { cause: 'deck-timeout' }`（不戦敗） | 180秒 |

## 使えるカード

オンライン対戦は **カードプール全体** から選べる（ストーリーモードの所持カードとは無関係）。
デッキ保存もストーリーモードとは別の保存領域にする（`localStorage` のキーを分ける）。

## ルームの設計（`src/online/room.ts`）

- **タイマーを内部に持たない**：各種の期限を計算して持ち、`nextDeadline()` で「次に起こす時刻」を伝え、その時刻に `tick()` を呼んでもらう方式。Cloudflareは同時に1つの alarm しか持てないため、この方式が合う。テストでは偽の時計を進めるだけで、60秒待たずに検証できる
- **席は token で識別する**：初回の `hello` で空き席に着き、token をサーバーが保存する。切断後は同じ token で同じ席に戻れる。他人は token を知らないので、席を奪えない
  - 画面側は token を **タブごと（sessionStorage）** に保存すること。localStorage だと、同じブラウザの2つ目のタブが1つ目を押し出してしまい、1人で2タブを使った動作確認ができなくなる
- **切断の猶予切れは、フェーズの時間切れより先に処理する**：切断者が自動選択されて試合が進むのを避けるため。両者とも切断なら、不戦敗ではなく勝者なしで終了する
- **表示名はサーバーが自動生成する**：クライアントが送った名前は使わない（不適切な名前の対策が不要になる）
- **保存と復元**：`snapshot()` / 復元で状態をJSONにできる。Cloudflare側では状態が変わるたびに保存し、サーバーがメモリから消えても復元できる（両者が同時にスマホをロックして切断した場合など）

## 実装済みの確認方法

- `npm test`：自動テスト（試合ルール、デッキ検証、通信メッセージ、ルーム、Cloudflare接続部分）
- `npm run dev:online` ＋ `npm run smoke:online`：本物のWebSocketでの通しの確認（Cloudflare不要）
- `worker/` で `npx wrangler dev` ＋ `npm run smoke:online`：Cloudflareと同じ環境での通しの確認
- ※ Cloudflare接続部分の自動テストは、PartyServerの公式ドキュメントどおりに作った代用品に対するもの。本物での確認は、上の2つの通しの確認で行う

## 画面の動作確認（ローカル）

ターミナルを2つ使い、ブラウザで2つのタブを開く。**自分1人でも、2つのタブで自分同士の対戦ができる**
（token はタブごとに別なので、同じブラウザの2つ目のタブが、1つ目を押し出すことはない）。

```bash
# ターミナル1：開発用のオンライン対戦サーバー
npm run dev:online
# ターミナル2：ゲーム本体
npm run dev
```

1. タブ1で `http://localhost:5173/?online=1&server=localhost:8787` を開く
2. 「オンライン対戦」→「ルームを作る」→ 招待リンクをコピー
3. タブ2に招待リンクを貼って開く（リンクには `server=localhost:8787` が引き継がれている）
4. 両方で「保存済みデッキ」を作る（または5枚選ぶ）→「このデッキで対戦する」

- 本番のCloudflareサーバーに接続して試すときは、`?server=` を付けずに `http://localhost:5173/?online=1` を開く
  （`localhost:5173` は `worker/wrangler.jsonc` の `ALLOWED_ORIGINS` で許可済み。Viteのポートが5174などに変わった場合は、そのポートを追加して再デプロイが必要）
- Vercelの確認用デプロイ（ブランチごとのURL）から本番サーバーに接続するには、そのURLを `ALLOWED_ORIGINS` に追加して再デプロイする

## 画面の仕様メモ

- **公開版には出さない**：タイトル画面の「オンライン対戦」は、URLに `?online=1`（または招待リンクの `?room=`）がある時だけ表示する。一度有効にしたタブでは保たれ、`?online=0` で解除できる
- **リロードで同じ席に戻る**：入室するとURLに `room=` が反映される。token は sessionStorage に保存されるので、リロードやモバイルでのタブ復帰で、同じ席・同じ試合に戻れる
- **選択は確定後に変更できない**：画面側は「カードを選ぶ → 決定」の2段階で、誤操作を防ぐ
- **オンライン専用の保存済みデッキ**：全カードから組める。ストーリーモードの保存済みデッキとは保存先（localStorageのキー）が別
- **既存部品の再利用**：盤面（BattleBoard）・手札・勝敗バナー・スコアボード・カード一覧・デッキ保存は、NPC対戦と同じ部品。サーバーから届く状態を本人視点に変換してあるので、そのまま渡せる
